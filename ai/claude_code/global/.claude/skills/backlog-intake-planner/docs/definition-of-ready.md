# 実装着手可否チェック（起票時）

実装に着手してよい状態かを、起票セッション内で確認する基準。正本は本ファイルのみ。
（英語の Definition of Ready / DoR に相当する考え方だが、**Backlog や requirements.md では「実装着手可否」と表記する**）

`backlog-intake-planner` は起票時に Read し、**判定結果はチャットにのみ**出す。`requirements.md` には書かない。

## 方針

- 薄い要求のまま実装に入らない。
- AI の推測は確定事項にしない（`requirements.md` の「前提」「確認したいこと」に分ける）。
- **不可**のとき `implementation-plan.md` は生成しない。handoff・実装セッションも起動しない。
- `implementation-plan.md` を書く前に必ず実施する。深掘り完了後は再判定する。

## チェック項目（9項目）

| #   | 項目                                          | 足りないと                     |
| --- | --------------------------------------------- | ------------------------------ |
| 1   | 目的（何を・なぜ・誰に）                      | 不可                           |
| 2   | 現状（今どうか・何が問題か）                  | 不可 または 条件付き可         |
| 3   | 期待結果（変更後どうなるか）                  | 不可                           |
| 4   | 対象範囲                                      | 不可                           |
| 5   | 対象外                                        | 条件付き可（不明なら「不明」） |
| 6   | 受け入れ条件                                  | 不可                           |
| 7   | 確認方法                                      | 条件付き可 以上で必須          |
| 8   | 危険領域（DB / 決済 / 権限 / 通知 / 横断 等） | 未整理なら 不可                |
| 9   | 未確定事項（宛先付き）                        | 実装を妨げるなら 不可          |

## 判定（3段階）

| 判定           | 意味                                                                 |
| -------------- | -------------------------------------------------------------------- |
| **可**         | 目的・範囲・受け入れ条件が揃い、未確定が実装を妨げない               |
| **条件付き可** | 大枠は明確。一部未確定だが、着手範囲と保留範囲を分けられる           |
| **不可**       | 目的・期待結果・範囲・受け入れ条件が欠ける。確認なしでは決められない |

## 実装開始ゲート

| 判定       | implementation-plan.md            | 実装       |
| ---------- | --------------------------------- | ---------- |
| 可         | 深掘り時に生成可                  | 可         |
| 条件付き可 | 着手可能範囲のみ。§0 に保留を書く | 条件付き可 |
| 不可       | **生成しない**                    | **不可**   |

## チャットへの出力（Backlog・requirements.md には載せない）

起票セッションの**チャット**に、次の短い形で提示する。

```markdown
## 実装着手可否（起票セッション内）

- 判定: 可 / 条件付き可 / 不可
- 理由: （1〜3行）
- 不足・確認が必要な点: （不可・条件付き可のとき。なければ「なし」）
- 深掘り（実装計画）を進めてよいか: はい / いいえ（不可のときは「いいえ」）
```

不足・確認が必要な点は、すでに `requirements.md` の「確認したいこと / 未確定」に書いた内容と矛盾させない。重複させない。
