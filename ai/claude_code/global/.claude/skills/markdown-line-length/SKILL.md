# markdown-line-length

行長を理由に、ソースへ物理改行を足さない。
長いときは次の順で対処し、どれも向かなければ長い 1 行のまま残す。

## 優先順

1. **構造化する** — 見出し・箇条書き・ネストに分ける
2. **文を短くする** — 冗長を削る
3. **長い 1 行のまま残す**

**禁止:** 文字数を収めるためだけの物理改行。文の途中でも、読点・句点の直後でも同じ。

## 理由

段落内の単一改行は、プレビューではスペースとして結合され、表示はほぼ 1 行のままになる。
句読点位置の改行でも、プレビューの読みやすさはほぼ変わらない。
リスト項目や見出しの途中改行は、結合や見出しの途切れでソースだけが壊れる。

## 行長の目安

- 目安は 80〜120 文字。上限ではない。超えても上記 1→2→3 で対処する。
- URL・テーブル・コードブロックは超過してよい。
- 見出しは折り返さない。長いなら見出しの文言を短くする。

## 例: 箇条書き

NG（項目の途中で改行して長さだけ調整）:

```markdown
- デプロイ前にステージングで回帰テストを実行し、
  失敗したケースをチケットへ紐づける。
```

OK（ネストで分ける）:

```markdown
- デプロイ前の確認
  - ステージングで回帰テストを実行する
  - 失敗したケースをチケットへ紐づける
```

## 例: 平文

NG（読点のあとで改行して長さだけ調整）:

```markdown
リリース手順はステージング確認のあと本番へ適用し、
問題があれば直前のタグへ戻す。
```

OK（構造化する）:

```markdown
## リリース手順

- ステージングで確認する
- 問題なければ本番へ適用する
- 問題があれば直前のタグへ戻す
```

OK（短くして 1 行）:

```markdown
ステージング確認後に本番適用し、問題時は直前タグへ戻す。
```
