# markdown-line-length

Markdown の意味と書き手が選んだ構造を、行長より優先する。
80〜120 文字は読みづらさに気づくための目安であり、上限や変更条件ではない。
長さだけを理由に既存の改行や構造を変えず、安全な改善がなければ長い 1 行を残す。

## Markdown 構文

次のブロック構文は、行長だけを理由に継続行へ折り返さない。

- 見出し、箇条書き、番号付きリスト、タスクリスト
- 引用、アラート、表の行
- Front Matter、リンク定義、脚注定義
- コード、HTML/JSX タグ、MDX の式や ESM、ディレクティブ

リンク、画像、URL、インラインコード、強調などのインライン構文も途中で分断しない。

箇条書きが実際に読み取りにくい場合は、意味に合う形だけを検討する。

- 対等な内容: 同じ階層の項目に分ける
- 親子関係: 短い親項目と子項目に分ける
- 1 論点への長い説明: 空行と必要なインデントを使い、同じ項目内の複数段落にする
- 冗長な内容: 意味を落とさず短縮する

文字数のためだけに項目を増やしたり、1 つの文を継続行へ折り返したりしない。
自然に分けられなければ、長い 1 行のまま残す。
箇条書き以外の構文も、意味を保てる短縮や構造化だけを行う。

## 通常の段落

平文は、長く読みづらい場合、または文脈上の区切りを明確にすると読みやすくなる場合だけ単一改行してよい。
目安を超えても、それだけでは短縮や改行を要求しない。

改行位置は、次の条件をすべて満たすものに限る。

- 完成した文の後にある `。`、`！`、`？` などの文末直後
- 前後の流れから見て自然な区切り
- Markdown のインライン構文の外側

文の途中や読点の直後では改行せず、句点のたびに機械的な改行もしない。
行末の 2 スペース、バックスラッシュ、`<br>` による hard break は追加しない。
空行は、話題や意味上の段落が変わる場合だけ使う。
安全な改行位置がなければ、意味を保てる短縮を検討し、それも適さなければ長い 1 行を残す。
行長だけを理由に、平文を見出しや箇条書きへ変えない。

## 例

NG（箇条書きを行長だけで途中改行する）:

```markdown
- デプロイ前にステージングで回帰テストを実行し、
  失敗したケースをチケットへ紐づける。
```

OK（親子関係に合わせて構造化する）:

```markdown
- デプロイ前の確認
  - ステージングで回帰テストを実行する
  - 失敗したケースをチケットへ紐づける
```

NG（平文を読点の直後で改行する）:

```markdown
リリース手順はステージング確認のあと本番へ適用し、
問題があれば直前のタグへ戻す。
```

OK（長い平文を自然な文末で区切る）:

```markdown
リリース前に、変更内容、監視項目、ロールバック手順、担当者、連絡経路を関係者全員で確認する。問題が見つかった場合は、その場で本番適用を止め、影響範囲を整理してから修正方針を決める。
問題がなく、関係者の承認も揃っている場合に限り、本番環境へ適用する。
```

OK（自然な区切りがなければ長い 1 行を許容する）:

```markdown
- 詳細は [長い名前を持つ運用ガイド](https://example.com/a-very-long-path-that-must-not-be-split) を参照し、記載された順序を変えずに確認する。
```
